# 智能宠物行为识别与环境联动系统

面向家庭宠物照护场景的本地 Web 应用 Demo。系统将图片/摄像头行为分析、猫叫音频理解、环境传感器读取、投喂控制和报警联动整合到一个 Gradio 界面中，用于功能验证、硬件联调和二次开发。

> 本仓库展示的是宠物行为分析与照护联动应用，不是通用视觉模型展示项目。底层视觉推理运行时只是实现依赖，对外功能以行为识别、风险提示、数据记录和硬件联动为中心。

## 项目功能

| 模块 | 功能说明 |
| --- | --- |
| 图片行为分析 | 上传图片或使用摄像头，识别进食、饮水、玩耍、睡眠、如厕、呕吐等行为线索，输出标注图、检测明细和摘要。 |
| 宠物健康建议 | 可选调用多模态接口，结合图片和本地检测结果输出行为判断、潜在风险与照护建议。 |
| 猫叫音频分析 | 上传或录制音频，直接理解猫叫情绪，输出情绪标签、置信度、紧急程度和建议。 |
| CH340/CH341 通信 | 通过 USB 转串口读取温度、湿度和食物重量，测试 JSON 收发、舵机控制和报警控制。 |
| 本地联动控制 | 根据重量变化判断进食事件，在投放上限和温度阈值约束下发送投喂或报警指令。 |
| 会话级记录 | 每个浏览器会话独立保存日志和音频记录，临时文件按保留周期自动清理。 |

## 实际使用流程

1. 在“图片行为分析”页上传图片或调用摄像头，查看行为标注、检测详情、环境状态和分析报告。
2. 在“音频叫声分析”页上传或录制猫叫，查看音频元信息、情绪分析和会话记录。
3. 在“CH340 硬件测试”页刷新 COM 口，读取传感器并发送原始 JSON、舵机或报警指令。
4. 在“本地联动控制”页执行一次投喂/报警判断，检查阈值、限次和异常返回。

## 技术流程

```text
图片/摄像头 ──> 本地行为识别 ──> 多模态分析（可选） ──> 风险提示与照护建议
猫叫音频 ────> 音频特征与元信息 ─> 音频理解（可选） ──> 情绪与紧急程度
CH340 传感器 ─> 温度/湿度/重量 ─> 本地规则判断 ─────> 舵机投喂或报警
```

没有外部 API Key 时，图片识别、音频基础信息和硬件联调仍可用于本地验证；配置 API Key 后再启用云端语义分析。

## 环境配置

- Windows 10/11；Python 3.10–3.12，建议使用 Conda。
- 浏览器建议使用 Chrome 或 Edge。
- 可选硬件：摄像头、CH340/CH341 串口模块、温湿度/重量传感器和舵机。
- 可选服务：阿里云百炼 DashScope API Key。
- 图片行为分析需要与项目类别匹配的本地权重；权重和训练产物默认被 `.gitignore` 排除。

### 安装依赖

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Gradio 版本已限制在 `>=4.44.0,<6.0`，避免新版接口差异造成启动失败。也可以运行：

```powershell
python setup_environment.py
```

### 准备权重

项目不提交大体积权重。默认训练输出目录为：

```text
runs/train/pet_behavior/weights/best.pt
```

也可以在启动时指定：

```powershell
python .\pet_behavior_gradio_app.py --weight .\path\to\your\best.pt
```

权重中的类别名称应与训练数据一致，应用不会假设所有模型支持相同类别。

### 启动应用

```powershell
python .\start_app.py
```

或直接运行：

```powershell
python .\pet_behavior_gradio_app.py
```

默认监听 `http://127.0.0.1:7861/`，不会自动开启公网映射。确需远程演示时，显式使用 `--enable-frp`，并先配置 FRP 服务端地址、端口和令牌。

### API Key 和本地数据

- 配置 API Key：启用图片语义分析和猫叫情绪分析。
- 不配置 API Key：仍可使用本地识别、音频元信息、串口测试和联动规则验证。
- API Key 与账号信息仅保存于当前运行实例的本地数据目录；公网部署前必须改用密钥管理、密码哈希、HTTPS 和访问控制。

## CH340 硬件协议

默认串口参数为 `115200` 波特率、`8/N/1`、UTF-8 编码、换行结束、读取等待 `0.5s`。应用使用一行一个 JSON 的文本协议：

```json
{"cmd":"temperature","action":"read"}
{"cmd":"humidity","action":"read"}
{"cmd":"weight","action":"read"}
{"cmd":"servo","id":1,"angle":90}
{"cmd":"alarm","level":"high"}
```

完整字段、返回格式、Arduino/ESP32 伪代码和联动逻辑见 [HARDWARE_SERIAL_PROTOCOL.md](HARDWARE_SERIAL_PROTOCOL.md)。

## 使用边界

本项目是研究、演示和工程联调工具，不是兽医诊断系统，也不是自动医疗设备。行为识别、情绪判断和风险提示可能出现误报或漏报；涉及持续呕吐、疼痛、呼吸异常、中毒、外伤或其他紧急情况时，应由专业兽医确认。

自动投喂和报警联动必须在真实硬件接入前完成限位、断电、空载、断连和异常返回测试。示例阈值不构成适用于所有宠物、粮食、设备或环境的安全参数。
